# Backtest.py 로직 요약

## 개요
`backtest.py` 파일은 `PortfolioConstructor` 클래스를 정의하여 금융 포트폴리오의 과거 성과를 시뮬레이션(백테스팅)하는 기능을 수행합니다. 사용자가 정의한 투자 전략(가중치)과 시장 데이터, 거래 비용 등을 바탕으로 포트폴리오의 가치 변화, 수익률, 거래 내역 등을 계산합니다.

## `PortfolioConstructor` 클래스

### 초기화 (`__init__`)
- 백테스팅에 필요한 기본 파라미터들을 설정합니다.
    - `mkt`: 시장 구분 (예: 'kospi', 'kosdaq')
    - `weights`: 포트폴리오 구성 가중치 데이터 (Pandas DataFrame 형태, 인덱스: 날짜, 컬럼: 종목 코드)
    - `init_invest`: 초기 투자 원금
    - `buy_commission`, `sell_commission`: 매수/매도 수수료율
    - `slippage`: 슬리피지 비율 (체결 오차)
    - `sell_tax`: 매도 세금 비율
    - `cash_rate`: 현금 보유 시 적용될 연 이자율
    - `rebal_timing`: 리밸런싱 시점 결정 방식 ('next' 또는 'now')
- `DataLoader`를 사용하여 필요한 시장 데이터를 로드합니다.
    - `price`: 종목별 수정 주가
    - `bm`: 벤치마크 지수
    - `trans_ban`: 거래 정지 정보
- 백테스팅 결과를 저장할 내부 변수들을 초기화합니다 (`_final_holdings_data`, `_transaction_summaries`, `_cash_balances`).

### 주요 속성 (Properties)
- `bday_dates`: 거래일 목록
- `formation_dates`: 포트폴리오 구성 기준일 목록 (weights 데이터의 인덱스)
- `rebalancing_dates`: 실제 리밸런싱이 수행되는 날짜 목록 (formation_date 이후 가장 가까운 거래일)
- `init_invest_date`: 첫 리밸런싱 날짜
- `last_invest_date`: 마지막 리밸런싱 날짜
- `transaction_costs_summary`: 리밸런싱 시점별 거래 비용 요약 (DataFrame)
- `cash_balance_summary`: 리밸런싱 시점별 현금 잔고 요약 (DataFrame)
- `pf_ret`: 포트폴리오의 일별 수익률 (DataFrame)
- `bm_ret`: 벤치마크의 일별 수익률 (DataFrame)
- `pf_quantity`: 리밸런싱 시점별 보유 종목 수량 (DataFrame)

### 주요 메서드

#### `get_quantity(formation_date, rebalancing_date, total_assets)`
- 특정 리밸런싱 시점(`rebalancing_date`)에 매수/보유할 종목별 수량을 계산합니다.
- `formation_date`의 가중치 정보를 사용합니다.
- `rebalancing_date`의 가격과 거래 정지 여부를 확인하여 투자 가능한 종목을 필터링합니다.
- 필터링된 종목들의 가중치 합이 1이 되도록 정규화합니다.
- 가용 투자 자산(`total_assets`)을 가중치에 따라 배분하고, 가격으로 나누어 목표 보유 수량을 계산합니다.

#### `pf_cashflow()`
- 백테스팅의 핵심 로직을 수행하여 포트폴리오의 일별 가치 변화를 계산합니다.
- 리밸런싱 주기별로 다음 과정을 반복합니다.
    1. **현금 이자 계산:** 보유 현금에 대해 기간별 이자를 계산하여 현금 잔고에 반영합니다.
    2. **리밸런싱 실행:** 총 자산 평가, 목표 수량 계산, 실제 거래 비용 계산, 현금 잔고 업데이트 등을 수행합니다.
    3. **일별 포트폴리오 가치 기록:** 현재 리밸런싱 기간 동안 보유 종목들의 일별 가격 변동을 반영하여 포트폴리오 평가 가치를 계산하고 기록합니다.
- 모든 리밸런싱 기간에 대한 계산이 완료되면, 일별 포트폴리오 가치(`Portfolio`), 현금 잔고(`Cash`), 총 자산(`Total`)을 포함하는 DataFrame을 반환합니다.

#### `_calculate_transaction_costs(current_quantity, previous_quantity, date, total_assets)`
- 현재 리밸런싱에서 발생하는 총 거래 비용을 계산합니다.
- 목표 보유 수량(`current_quantity`)과 이전 보유 수량(`previous_quantity`)을 비교하여 순매수/순매도 수량을 파악합니다.
- 해당 리밸런싱 날짜(`date`)의 가격을 기준으로 매수 가치와 매도 가치를 계산합니다.
- 설정된 수수료율, 슬리피지, 세금 비율을 적용하여 매수 비용과 매도 비용을 각각 계산합니다.
- 총 거래 비용과 상세 거래 내역(매수/매도 금액, 수량, 비용 등)을 반환합니다.

## 리밸런싱 타이밍 로직(Rebalancing Timing Logic) 상세 설명

### 리밸런싱 날짜 결정 메커니즘
`rebal_timing` 파라미터는 형성 날짜(formation date)로부터 실제 리밸런싱 날짜(rebalancing date)를 결정하는 방식을 지정합니다:

1. **`next` 옵션**: 
   - 형성 날짜 **직후**의 첫 번째 거래일을 리밸런싱 날짜로 사용합니다. 
   - 이 옵션은 형성 날짜와 같은 날에는 절대 리밸런싱하지 않고, 반드시 그 다음 거래일에 리밸런싱합니다.
   - 내부적으로 `np.searchsorted(..., side='right')` 함수를 사용하여 형성 날짜보다 큰 첫 번째 거래일을 찾습니다.

2. **`now` 옵션**:
   - 형성 날짜가 거래일이면 **당일**에 리밸런싱합니다.
   - 형성 날짜가 거래일이 아니면(휴장일 등) 다음 거래일에 리밸런싱합니다.
   - 내부적으로 `np.searchsorted(..., side='left')` 함수를 사용하여 형성 날짜 이상인 첫 번째 거래일을 찾습니다.

이 결정 과정은 `rebalancing_dates` 속성에서 이루어지며, 모든 형성 날짜에 대한 리밸런싱 날짜를 미리 계산하여 캐싱합니다.

### 리밸런싱 날짜와 형성 날짜 매핑
`pf_cashflow()` 메서드는 `date_map` 딕셔너리를 구성하여 각 리밸런싱 날짜가 어떤 형성 날짜에서 비롯되었는지 추적합니다. 이는 리밸런싱 시점에 올바른 가중치 정보를 사용하기 위함입니다:

1. 모든 리밸런싱 날짜에 대해 루프를 돌며:
   - 각 형성 날짜를 선택된 `rebal_timing` 방식에 따라 리밸런싱 날짜로 변환합니다.
   - 계산된 리밸런싱 날짜와 실제 리밸런싱 날짜가 일치하면 매핑을 기록합니다.

2. 매핑이 실패하는 경우(예: 동일한 리밸런싱 날짜에 여러 형성 날짜가 매핑되는 경우) 대체 로직 실행:
   - 해당 리밸런싱 날짜 이전의 가장 최근 형성 날짜를 사용합니다.

## 현금 제약과 스케일링 팩터 로직(Cash Constraints and Scaling Factor Logic) 상세 설명

백테스트 시뮬레이션에서 현실적인 거래 상황을 모델링하기 위해 중요한 요소는 현금 제약 조건에 따른 매수 금액 조정입니다. 이를 위해 스케일링 팩터(scaling factor) 방식을 적용합니다.

### 1. 이상적인 포트폴리오 구성 계산 (Ideal Portfolio Construction)

각 리밸런싱 시점에서, 먼저 현금 제약 없이 이상적인 포트폴리오 구성을 계산합니다:

```python
ideal_target_quantity = self.get_quantity(
    formation_date=formation_date,
    rebalancing_date=rebalancing_date,
    total_assets=total_assets_before_rebalance
)
```

이 단계에서는:
- `formation_date`의 종목별 가중치
- `rebalancing_date`의 종목별 가격
- 리밸런싱 시점의 총 자산 가치(`total_assets_before_rebalance`)

를 기반으로 이상적인 보유 수량을 계산합니다. 이 때 현금 제약은 고려하지 않습니다.

### 2. 이상적인 거래에 필요한 현금 계산 (Ideal Trade Cash Calculation)

다음으로, 이상적인 포트폴리오를 구성하기 위해 필요한 거래 금액과 비용을 계산합니다:

```python
buy_value_ideal, sell_value_ideal, buy_cost_ideal, sell_cost_ideal, _, _ = 
    self._calculate_transaction_costs(
        ideal_target_quantity, 
        current_quantity, 
        rebalancing_date, 
        total_assets_before_rebalance, 
        calculate_summary=False
    )
```

이를 통해 다음 값들을 얻습니다:
- `buy_value_ideal`: 이상적인 매수 금액 (비용 제외)
- `sell_value_ideal`: 이상적인 매도 금액 (비용 제외)
- `buy_cost_ideal`: 이상적인 매수에 소요되는 비용 (수수료, 슬리피지)
- `sell_cost_ideal`: 이상적인 매도에 소요되는 비용 (수수료, 슬리피지, 세금)

### 3. 현금 제약 조건 확인 (Cash Constraint Check)

다음으로, 매수에 필요한 총 현금과 가용 현금을 비교합니다:

```python
cash_from_sells_ideal_net = sell_value_ideal - sell_cost_ideal
cash_needed_for_buys_gross = buy_value_ideal + buy_cost_ideal
cash_available_after_ideal_sells = cash_balance + cash_from_sells_ideal_net
```

- `cash_from_sells_ideal_net`: 매도 후 얻는 순현금 (매도 금액 - 매도 비용)
- `cash_needed_for_buys_gross`: 매수에 필요한 총현금 (매수 금액 + 매수 비용)
- `cash_available_after_ideal_sells`: 매도 후 가용 현금 (기존 현금 + 매도 순현금)

### 4. 스케일링 팩터 적용 (Scaling Factor Application)

매수에 필요한 현금이 가용 현금보다 많을 경우, 매수 규모를 조정하기 위한 스케일링 팩터를 계산합니다:

```python
if cash_needed_for_buys_gross > cash_available_after_ideal_sells + 1e-6:
    # 현금 부족 상황
    
    if cash_needed_for_buys_gross <= 1e-6:
        scale_factor = 0.0  # 매수할 것이 없음
    elif cash_available_after_ideal_sells < 0:
        scale_factor = 0.0  # 가용 현금이 음수
    else:
        # 실제 스케일링 팩터 계산
        scale_factor = cash_available_after_ideal_sells / cash_needed_for_buys_gross
        scale_factor = max(0.0, min(1.0, scale_factor))  # 0~1 사이로 제한
```

스케일링 팩터 값의 의미:
- `1.0`: 이상적인 매수를 100% 실행 가능 (현금 제약 없음)
- `0.5`: 이상적인 매수 금액의 50%만 실행 가능
- `0.0`: 매수 불가능 (가용 현금 부족)

### 5. 최종 목표 수량 계산 (Final Target Quantity Calculation)

스케일링 팩터가 계산되면, 이를 적용하여 최종 목표 수량을 산출합니다:

```python
union_index = ideal_target_quantity.index.union(current_quantity.index)
ideal_target_aligned = ideal_target_quantity.reindex(union_index, fill_value=0.0)
current_aligned = current_quantity.reindex(union_index, fill_value=0.0)

# 이상적인 포트폴리오와 현재 포트폴리오의 차이 계산
net_trades_ideal = ideal_target_aligned - current_aligned

# 포트폴리오 비율을 유지하면서 현재 포트폴리오에서 이상적 포트폴리오 방향으로 
# scale_factor 비율만큼만 이동 (매수/매도 균등하게 조정)
final_target_quantity = (current_aligned + net_trades_ideal * scale_factor).round(8)
```

이 과정에서 주요 포인트:
1. `scale_factor`가 1.0이면 이상적인 포트폴리오로 100% 이동 (제약 없음)
2. `scale_factor`가 0.5면 현재 포트폴리오에서 이상적 포트폴리오 방향으로 50%만 이동
3. `scale_factor`가 0.0이면 현재 포트폴리오 유지 (거래 없음)
4. 매수와 매도 모두 동일한 비율로 스케일링하여 원래 목표했던 포트폴리오의 자산 비율을 유지

이 방식은 현금 제약이 있더라도 포트폴리오의 상대적 비중을 유지하면서 전체 규모만 조정합니다. 따라서 현금이 부족하더라도 포트폴리오의 투자 전략과 자산 배분 비율은 유지됩니다.

### 6. 최종 거래 실행 (Final Trade Execution)

최종 목표 수량이 결정되면, 실제 거래 비용과 현금 흐름을 계산합니다:

```python
buy_value, sell_value, buy_cost, sell_cost, total_transaction_cost, transaction_summary = 
    self._calculate_transaction_costs(
        final_target_quantity, 
        current_quantity, 
        rebalancing_date, 
        total_assets_before_rebalance, 
        calculate_summary=True
    )

# 현금 업데이트
net_cash_flow_from_trades = (sell_value - sell_cost) - (buy_value + buy_cost)
cash_balance += net_cash_flow_from_trades
```

### 7. 실제 보유 내역 저장 (Actual Holdings Storage)

각 리밸런싱 이후, 실제 최종 보유 수량을 `_final_holdings_data` 리스트에 저장합니다:

```python
self._final_holdings_data.append({
    'Date': rebalancing_date,
    'Quantity': final_target_quantity.copy()
})
```

이 데이터는 `get_holdings_snapshot()` 메서드에서 실제 포트폴리오 보유 내역을 확인하는 데 사용됩니다.

## 백테스팅 프로세스 흐름
1. `PortfolioConstructor` 객체 생성 시 초기 파라미터 설정 및 데이터 로딩.
2. `pf_cashflow()` 또는 `pf_ret` 속성 호출 시 백테스팅 시작.
3. 첫 리밸런싱 날짜부터 마지막 리밸런싱 날짜까지 루프 실행.
4. 각 리밸런싱 시점마다:
    - 현금 이자 계산 및 반영.
    - 이상적인 목표 수량 계산.
    - 현금 제약 확인 및 스케일링 팩터 적용.
    - 최종 목표 수량 결정.
    - 실제 거래 비용 계산 및 현금 잔고 업데이트.
    - 실제 보유 수량 저장.
    - 다음 리밸런싱까지의 일별 포트폴리오 가치 계산 및 기록.
5. 루프 종료 후, 전체 기간의 일별 포트폴리오 가치, 현금 잔고, 총 자산을 DataFrame으로 취합하여 반환.
6. 계산된 결과를 바탕으로 `pf_ret`, `bm_ret`, `transaction_costs_summary`, `get_holdings_snapshot()` 등 메서드를 통해 추가 정보 제공.
